Your Consensus plan sets three things: how many papers each search returns, which fields come back on each paper, and your monthly search quota. This page covers all three, plus how to handle rate limiting.

## Papers per search

Every search returns a ranked page of papers. The maximum number per search depends on your tier.

| Tier | Papers per search | Notes |
|------|-------------------|-------|
| Anonymous (no account) | 3 | Unlimited searches, reduced fields |
| Free | 10 | Full abstracts |
| Pro | 20 | Adds `study_type` and `takeaway` |
| Deep | 20 | Adds `study_type` and `takeaway` |
| Teams | 20 | Adds `study_type` and `takeaway` |
| Enterprise | Custom | Adds `full_text_chunks`, DOI, and advanced access |

On the REST API, request up to this many results with `page_size`. Values above your tier cap are clamped to the cap. To read beyond the first page, use [pagination](/api-reference/pagination).

## Field access by tier

Higher tiers return richer metadata on every paper. Fields are additive: each tier includes everything the tiers below it return.

| Field group | Available on |
|-------------|--------------|
| `title`, `authors`, `abstract`, `journal_name`, `publish_year`, `citation_count`, `url` | All tiers, including Anonymous |
| `study_type`, `takeaway` (AI summary) | Pro, Deep, Teams, Enterprise |
| `full_text_chunks`, DOI, advanced access | Enterprise |

<Note>
  `semantic_score` is returned only when you set `include_semantic_score=true`, and only for the top 50 or so results. `full_text_chunks` is returned only when you set `include_full_text_chunks=true` on an Enterprise plan. See [Enterprise full text and fields](/enterprise/full-text-and-fields).
</Note>

## Rate limiting

When you exceed your rate limit, the API responds with HTTP `429 Too Many Requests` and a `Retry-After` header telling you how many seconds to wait before trying again.

Respect `Retry-After` and back off instead of retrying immediately. A small, robust pattern in Python:

```python
import time
import requests

def search(params, api_key, max_retries=5):
    url = "https://api.consensus.app/v1/search"
    headers = {"x-api-key": api_key}

    for attempt in range(max_retries):
        resp = requests.get(url, headers=headers, params=params)

        if resp.status_code == 429:
            # Honor the server's Retry-After, falling back to exponential backoff.
            retry_after = resp.headers.get("Retry-After")
            wait = int(retry_after) if retry_after else 2 ** attempt
            time.sleep(wait)
            continue

        resp.raise_for_status()
        return resp.json()

    raise RuntimeError("Rate limit not cleared after retries")
```

<Tip>
  For production workloads, add jitter and a ceiling to the backoff, and cache results you fetch repeatedly so you stay well under your limit.
</Tip>
