title: "Authentication"
description: "How the Consensus MCP server authenticates clients: OAuth 2.1 with PKCE, Enterprise Bearer tokens, and anonymous access."
---

The Consensus MCP server supports three ways to authenticate. Most clients use OAuth automatically, so there is usually nothing to configure.

## OAuth 2.1 (default)

The server uses the OAuth 2.1 Authorization Code flow with PKCE and dynamic client registration. When your client first calls Consensus, it registers itself, opens a browser window for you to sign in and approve access, and receives a token. Most MCP clients (Claude, ChatGPT, Cursor, Codex, VS Code, Windsurf) run this flow for you, with no keys to copy.

<Steps>
  <Step title="Connect the client">
    Add the server as described in [Connect a client](/mcp/connect).
  </Step>
  <Step title="Approve access">
    On the first tool call, a browser window opens. Sign in to Consensus and approve access.
  </Step>
  <Step title="Search">
    Your client stores the token and uses it for later calls automatically.
  </Step>
</Steps>

<Accordion title="OAuth discovery endpoint">
  Clients that support discovery read the server metadata from:

  ```
  https://consensus.app/.well-known/oauth-authorization-server
  ```

  This exposes the authorization and token endpoints and the supported flows, so compliant clients can register and authorize without manual configuration.
</Accordion>

## Enterprise Bearer token

Enterprise plans can authenticate with a static API key instead of OAuth by sending it as a Bearer token:

```
Authorization: Bearer YOUR_API_KEY
```

Use this for headless agents, shared services, or any client where an interactive browser login is not practical. See [Enterprise](/enterprise/overview) for how to get a key and what Enterprise access adds.

## Anonymous access

You can call the server without signing in. Anonymous access works, but it is aggressively rate limited and returns a reduced set of fields. Sign in with OAuth for higher limits and the full field set for your plan.

<Note>
  Field access follows your plan. Anonymous and Free return the core fields (title, authors, abstract, journal, year, citation count, url); Pro and above add `study_type` and `takeaway`. See [Tools](/mcp/tools) for the full response.
</Note>

## Re-authenticating after a token expires

OAuth tokens expire after several hours. When a token expires, the next tool call can fail with a `401` error. Reconnect to get a fresh token:

- **Claude Code:** run the `/mcp` command and reconnect Consensus.
- **Other clients:** disconnect and reconnect Consensus, or approve the browser prompt again, from the client's MCP or connector settings.

<Tip>
  A sudden `401` after hours of working usually means the token expired, not that anything is misconfigured. Re-authorizing resolves it.
</Tip>
